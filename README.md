# 네이버 뷰티·패션 블로그 자동화

매일 여자 연예인 뷰티·패션 소스를 크롤링 → **제목 1개 자동 확정** → 본문 완성 →
`output/날짜/완성본.txt` 에 대기. 아침에 열어서 네이버에 복붙만 하면 끝.

diet-blog 를 통째로 복제한 뒤 주제만 갈아끼운 저장소다.
파이프라인·검증기·제목 점수·루틴 구조는 동일하고, config 의 어휘 사전,
prompts 의 리스크 규칙, 사진 버킷 셋만 뷰티판이다.

```
run.ps1 (윈도우) / run.sh → main.py
  crawler.py       네이버 검색 API 또는 Google News RSS로 소스 수집
  store.py         인물 45일 쿨다운 / 기사·CTA 중복 차단 (SQLite)
  prompts.py       팩트시트·제목·본문 프롬프트 + 리스크 규칙  ★규칙은 여기 한 곳
  titles.py        제목 10개 → 점수 → 1개 확정   ★핵심
  writer.py        본문 생성 + 자동 수리 루프 (API 경로)
  brief.py         에이전트에게 넘길 지시서 생성 (키 없는 경로)
  draft_to_body.py 평문 초안 → 점자 부착 + 길이 점검
  validator.py     줄수·점자빈칸·단락을 파이썬이 직접 셈  ★핵심
  images.py        팩트시트 → 사진 버킷 선택 → 정사각 가공
  config.py        튜닝은 여기서만

  photo_library.py / image_sourcing.py / build_photo_library.py
                   car-blog에서 가져온 사진 소싱·순환 엔진 (주제 무관, 그대로 재사용)
```

## ★ 이미지 조달이 소재를 결정한다 (2026-08-10 사용자 확정)

**이 시스템의 목표는 발행 저항 최소화다. 발행자가 사진을 찾느라 쓰는 시간이 최대 병목이었다.**
그래서 소재를 이미지 조달 난이도로 나눠 관리한다.

| 소재 | 이미지 조달 | 방침 |
|---|---|---|
| 뷰티 (피부·동안·리즈시절·관리 습관·솔직 발언) | 인물 사진 없이도 성립. 스톡 소재컷으로 커버 | **선호. 하루 절반을 여기서** |
| 패션 — 본인 SNS 게시물 | 그 계정만 열면 끝 (`sns_materials`) | 허용. 이미지메모.txt 에 링크 |
| 패션 — 언론사 사진 (시상식·공항·화보) | 어느 기사인지 검색해야 함 → 시간 폭발 | **본문의 축으로 금지.** 곁가지 한 줄까지 |

- 본문·제목에 **착장을 특정하지 않는다.** 착장 명칭은 글 전체 3회 이내 —
  `validate.py` 가 실제로 센다. 옷 이름 대신 반응·발언·숫자·관리법을 쓴다.
- 각 방에 `이미지메모.txt` 가 자동으로 생긴다 (SNS 소재 목록 + 인스타 검색 링크).
- 소재 배분: `config.ANGLE_RATIO` = 뷰티 5 : 패션 5.

**⚠️ 2026-08-07 사용자 확정: 스탠바이에 이미지를 넣지 않는다 (`IMAGE_COUNT = 0`).**
발행에 쓸 수 없는 이미지라 제외. 아래 사진 절은 다시 켤 때(IMAGE_COUNT>0)의 기록이다.
글이 뷰티 중심으로 바뀌면 스톡 소재컷이 다시 어울리므로, 그때 숫자만 올리면 된다.

**이미지는 인물 없는 소재컷만 쓴다.** 카드뉴스(텍스트 얹은 이미지)도, 인물 컷도 쓰지 않는다.
사람이 크게 나오는 컷은 글과 따로 놀고 초상 문제 소지도 있다.
**장수가 모자라면 모자란 대로 내보낸다.**
버킷 목록은 `config.FOOD_BUCKETS_ONLY` (이름은 diet 시절 그대로, 내용은 뷰티 10종),
정사각 1080px로 잘라 가공 없이 나간다.

## ★ 2026-08-13 사용자 확정 — 사고 3건과 그 방어선

같은 날 나간 김고은 편 한 글에서 세 가지가 동시에 터졌다. 셋 다 코드로 막았다.

| 사고 | 원인 | 방어선 |
|---|---|---|
| 배우 김고은과 '솔로지옥5' 김고은이 한 글에 섞임 | 검색이 이름으로만 긁는다 | `crawler.drop_namesakes()` 가 소스 단계에서 제외 + 팩트시트 `identity_anchor` 필수 + `validate.py` 가 본문 재검사 |
| "스포츠조선 인터뷰에서" 같은 매체명 노출 | **프롬프트가 출처를 밝히라고 시키고 있었다** | 프롬프트를 뒤집고 `config.MEDIA_TERMS` 로 두 검증기가 실제로 셈 |
| 밋밋한 제목이 1위로 확정 | `head_number(+30)` 가 "34세"의 나이 숫자만으로 터졌다 | 나이는 숫자로 안 침 + `head_thin(-14)` · `vague_tail(-12)` · `head_scene(+22)` 신설 |
| 인물이 통째로 빠진 제목 10개 ("부활절 인사 남긴 근황.jpg") | **v13이 모델 자평(`heat`)으로 1위를 뽑고 있었다** | 확정을 `titles.score()` 로 이관 + `no_person(-25)` · `too_short(-20)` + 확정 하한 30점 |

- **매체명·기사 출처는 본문에 한 글자도 쓰지 않는다.** 우리는 기사를 옮기는
  곳이 아니라 홈판 블로거다. 발언은 "이렇게 말한 적이 있어요" 로 푼다.
  팩트시트의 `quote_sources` 는 발언이 실재하는지 확인하는 검증용이다.
- **제목 앞 20자에 "[나이]세 배우"를 넣지 않는다.** 어느 제목에나 붙는 빈칸이라
  홈판 목록에서 아무 그림도 안 그려진다. 숫자(나이 제외)·장면어·관계 실명·
  신호어·모순 중 2개를 앞으로 당긴다.
- 새 매체명·새 동명이인을 발견하면 `config.MEDIA_TERMS` / `config.NAMESAKE_DROP`
  에 한 줄 추가한다. 목록에 없는 건 코드가 모른다.

## 설계 원칙 3개

### ① 제목은 LLM이 고르지 않는다

모델은 10개만 만들고, **선택은 파이썬 점수 함수**가 한다.
홈판은 앞 20자만 노출되므로 총점의 절반 이상이 앞 20자에서 나온다.

```
  90  48kg인데 식단표가 없다는 34세 배우, 대신 새벽마다 한강을 뛴다
  86  30년째 같은 피부라는 58세 여배우의 아침 습관
  63  "165cm 43kg" 유지한다는 62세 여배우의 공항패션
  24  "엄격한 식단 안 한다는" 34세 배우, 그런데 피부는 도자기라는데
 -63  부활절 인사 남긴 근황.jpg
-999  성형 의혹 불거진 40대 여배우의 근황
```

3번이 낮은 이유는 BMI 15.8이라 저체중 스펙(-15)에 걸렸기 때문이다.
4·5번은 2026-08-13에 실제로 확정됐던 제목이다 — 그날 이후 하한(30점)에 걸려
반려된다. 6번은 의혹 제기 = `BANNED_HOOKS` 라 즉시 탈락이다.

**v13(하루 10편) 경로도 2026-08-13부터 이 점수 함수로 확정한다.** 예전엔 모델이
자기 제목에 매긴 `heat` 로 1위를 뽑아서 이 원칙이 v13에서만 깨져 있었다.
지금 heat 는 동점일 때 순서만 가른다.

**튜닝은 프롬프트가 아니라 `config.WEIGHTS` 숫자로 한다.**
점수 계산이 문서의 실측값과 맞는지는 `python titles.py` 로 확인할 수 있다.

### ② 형식 검증은 프롬프트가 아니라 코드로

모델은 줄을 못 센다. 체크리스트를 100개 넣어도 "통과했습니다"라고 자기보고만 한다.
`validator.py` 가 실제로 세고 → 위반 목록을 되먹여 재작성(최대 3회) →
마지막에 `polish()` 가 기계적으로 강제 복구한다.

검사 항목: 줄 끝 U+2800 부착 / 빈 줄 U+2800×3 / 한 줄 9~19자(권장 13~17) /
한 단락 ≤3줄 / 내용 줄 66~86 / **네이버 공백제외 850~950자(점자 포함·해시태그 제외,
thin은 700~) — 네이버는 점자 빈칸을 글자로 센다(실측)** /
불릿 0개 / 해시태그 정확히 8개 /
소제목 형식(마크다운 기호 노출 0) / CTA 포함 / 수치 아라비아 숫자 /
실명·과잉높임·지침용어 누출 0

> ⚠️ **버그 주의**: 파이썬 `strip()`은 U+2800을 공백으로 인식하지 않는다.
> 빈 줄 판정은 반드시 `line.replace('⠀','').strip() == ''` 로 해야 한다.
> 이거 틀리면 줄 수가 전부 어긋난다. `validator.is_blank()` 가 그 구현이다.

### ③ 못 구하면 뺀다

소스가 얇으면 짧게 낸다. 사진이 없으면 없이 간다.
**억지로 채우는 순간 창작과 리스크가 들어온다.** 이게 이 파이프라인의 기본 태도다.

`crawler.assess_richness()` 가 `thin` 을 반환하면 분량 하한이 내려간다.
구글 뉴스 경로는 헤드라인만 얻으므로 대개 `thin` 이 나오는데, 그게 정상이다.

| `PEXELS_API_KEY` 등 | 이미 받아둔 사진 라이브러리를 쓴다 | 라이브러리를 새로 채울 수 있다 |

401(Scope Status Invalid)이 난다. 보류 확정 — 구글 폴백으로 돌린다.

뷰티·패션 소재(화장품·가방·구두)는 스톡 3사에 다이어트 음식보다 훨씬 풍부하다.
Pexels 403 은 키 문제가 아니라 Cloudflare 봇 차단 — 브라우저 UA 필수 (실측).

## 운영 — 경로 B: 에이전트 (키 없을 때)

파이썬이 수집·제목 점수·형식 검증을 하고, **글 쓰는 일만 클로드 코드가 한다.**
`/daily` 슬래시 커맨드가 이 4단계를 그대로 몰고 간다.

```bash
.\run.ps1 --stage crawl       # → 1_팩트시트_지시서.md
   # 에이전트가 factsheet.json + title_candidates.json 작성
.\run.ps1 --stage title       # 제목 확정 → 2_본문_지시서.md
   # 에이전트가 draft.txt 작성
python draft_to_body.py state\work\<날짜>\draft.txt state\work\<날짜>\body.txt
.\run.ps1 --stage finish      # 검증 → 완성본.txt + 사진
```

`--stage finish` 는 위반이 남으면 **종료 코드 4**로 끝나고 `위반목록.md` 를 남긴다.
`draft.txt` 를 고쳐 다시 돌리는 게 정석이고, `--polish` 는 최후 수단이다
(기계가 어절 단위로 잘라서 읽는 맛이 죽는다).

`--date 2026-08-04` 로 지난 폴더를 다시 마감할 수 있다.

클로드 코드 슬래시 커맨드: `/daily`, `/pick 전지현`

산출물 — 아침에 폴더를 열면 복붙할 것만 보인다:

```
output/날짜/완성본.txt     ← 이것만 복사하면 끝
output/날짜/1번 사진.jpg …   ← 소재 컷 (최대 4장)
state/work/날짜/             ← 팩트시트·제목점수·소스 등 (output 밖)
```

## ⚠️ 이 주제 고유의 리스크

다이어트의 의료 리스크 자리에 **화장품법 표시광고·명예훼손** 리스크가 들어온다.
아래는 `prompts.py` 에 규칙으로 박혀 있고, 일부는 `validator.py` 가 실제로 검사한다.

**실존 인물**
- **효능 단정 금지.** "이 크림 바르면 미백된다"(X) → "본인이 애용한다고 밝혔다"(O).
  화장품 효능 단정은 화장품법 표시광고 위반 소지가 있다.
- **시술·피부과는 본인이 공개 언급한 것만.** 본인 해명·고백 발언은 최상급 후킹,
  남이 제기한 성형 의혹·시술 추측은 금지 (`BANNED_HOOKS` 에 걸리면 탈락).
- **브랜드 실명은 공개된 사실만.** 앰버서더·착용 보도는 OK. "짝퉁 아니냐" 류
  비교·폄하 금지. 특정 제품 구매 유도 구성 금지.
- 외모 **하향 평가 금지** ("망가졌다", "늙었다"). 상향 묘사("여신", "동안")는 자유.
- 인용에는 방송 프로그램명이나 매체명을 본문에 밝힌다
  (`factsheet.quote_sources` 가 그 자리다. 출처가 없으면 그 발언은 버린다).

## 안전 가드 (config에서 조정)

- `AD_DISCLOSURE` / `HEALTH_DISCLAIMER` — **기본 OFF (사용자 결정).**
  쇼핑커넥트(대가성 링크)를 실제로 붙이는 날에는 `AD_DISCLOSURE` 를 다시 켜야 한다 —
  공정위 추천·보증 심사지침 대상이라 표기 없이 링크만 넣으면 리스크가 매일 쌓인다.
- `EXTREME_WORDS`(외모 조롱 계열) / `BANNED_HOOKS`(의혹 제기·짝퉁·뒷광고) — 걸리면 탈락.
- **실명은 제목 블라인드 / 본문 도입부 리빌.** 제목에 나오면 그 제목은 탈락하고,
  본문 도입부에 리빌이 없으면 검증기가 잡는다. 다른 여자 연예인 실명은 본문에도 금지.

## v13 미모·이슈 시스템 (소스 입력형 — 일일 자동 파이프라인과 별개)

소스(기사 묶음·방송 텍스트)를 사람이 넣으면 최대 화력 제목 10개 + 본문을 뽑는
반자동 시스템. 일일 자동 파이프라인(main.py)과 규격이 다르다:
제목은 `.jpg` 마감, 분량은 **공백·점자 제외 850~1000자**, 소제목은 `**"소제목"**`.

**하루 10편 스탠바이가 기본값이다** (일일 자동 1편 + v13 9편, 사용자 확정 2026-08-05).

```bash
python pipeline.py --plan 9            # 오늘 쓸 인물 추천 (최근 45일 미사용)
python pipeline.py --auto 전지현       # crawler로 소스 자동 구성 + 세션 시작
python pipeline.py --source 소스.txt   # (수동 소스로 시작할 때)
python pipeline.py --stage titles      # 검증1 → B_지시서
python pipeline.py --stage body        # 검증2 → 1위 자동 확정 → C_지시서
python pipeline.py --wrap              # draft_plain.txt → body.txt 점자 변환
python pipeline.py --stage finish      # 검증3 → output/MMDD/번호/완성본.txt
python pipeline.py --retitle 3         # 예비 3번 제목으로 본문 재생성
python validate.py                     # 자체 테스트
```

- 지시서(state/v13work/…)는 에이전트가 처리한다 — API 키 불필요.
- **본문은 draft_plain.txt 에 평문으로 쓰고 --wrap 으로 변환한다.**
  점자 빈칸을 손으로 붙이면 반드시 빠진다 (실측).
- ⚠️ --auto/--source 는 세션 포인터(CURRENT)를 옮긴다.
  **한 인물을 finish 까지 끝낸 뒤에** 다음 인물을 시작할 것.
- 분량: 공백 제외 **820자 안팎 (허용 780~900)** — 2026-08-05 사용자 하향 조정.
  내용 줄 66~72줄이면 한 번에 들어간다. 길어지면 마지막 챕터·마무리를 짧게 —
  앞은 두껍게, 끝은 가볍게.
- 마감틀·CTA·연결 문장은 data/ 풀에서 **코드가 랜덤 1개만 주입** (모델에게 풀을 안 준다).
- state.json 이 최근 글들의 마감·CTA·후킹·인물을 기억해 도배를 코드로 차단한다.
- 유일한 금지선: 팩트시트에 없는 사실·발언·직업·숫자 창작 금지. 화력은 표현에서.
- 소재 필터 (실측 판단례): 실명 없는 기사(동명이인 위험)·발언 주체가 모호한 기사·
  정치 논란·질병 기사는 버린다. 당사자가 부인한 설은 confirmed:false 로만.
